# Example output (offline test mode)

**These are not agent output.** They were drafted by the deterministic offline-test-mode template used for CI, and show the structure, the gate and the audit trail. Scored agent runs are added when the demo run happens.

Generated by `python3 -m agent.run_playbook` on the committed fixtures with no API key, so the deterministic template drafted both briefs. Every company and person is fictional. Absolute paths were replaced with `$WIRE_OUT_DIR`. Regenerate with `WIRE_OUT_DIR=/tmp/wire python3 -m agent.run_playbook`.

| File | What it shows |
|---|---|
| `brief-hs-1001.md` | The Canadian bank: what changed (SR 26-2), what is certain (OSFI E-23, B-13), what depends on structure (every line "Confirm", including "SR 26-2 applicability requires confirmation"), next step. |
| `brief-hs-1002.md` | The US bank: same structure, no home-regulator lines. |
| `approval-request-hs-1001.json`, `approval-request-hs-1002.json` | The requests routed to the named account owner: `status: pending`, `send: false`. |
| `audit-records-hs-1001.jsonl` | Every R-17 record the run wrote for the Canadian bank, in order: enrich, score, route, create. |
| `offline-test-mode-scores.json` | The same run scored by `python3 -m evals.score_run` (22/22), labelled as offline test mode. |
| `run-summary.json` | Every account's outcome and reason, the watch list, and each playbook's status and metrics. |

No model-drafted example exists: no API key was available when this was built.
